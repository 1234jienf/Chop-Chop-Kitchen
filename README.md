# Chop-Chop Kitchen

목소리로 칼질하고 불을 조절하며, 세 명의 셰프가 한 공정씩 이어서 4코스 요리를 완성하는 브라우저 기반 협동 요리 게임입니다.

각 플레이어는 정해진 순서대로 에피타이저, 스타터, 메인, 디저트의 조리 공정을 맡습니다. 마이크의 리듬·음량·음정과 음성 인식 결과로 수행 정확도를 계산하고, 하루가 끝나면 코스별 점수와 매출, 손님 취향 보너스를 정산합니다.

## 주요 기능

- 동일한 방 코드로 참가하는 3인 실시간 협동 플레이
- 직접 학습한 Teachable Machine 음성 분류 AI 모델을 활용한 조리 입력 인식
- 자르기, 끓이기, 굽기, 오븐 굽기, 섞기, 뿌리기·붓기 미니게임
- 4개 카테고리, 총 15개 레시피에서 손님 취향과 난이도에 맞춘 4코스 구성
- 공정 정확도에 따른 코스 점수, 별점, 매출 계산
- OpenAI GPT-4o mini를 사용한 선택형 손님 리뷰와 API 장애 시 로컬 리뷰 폴백
- 데스크톱과 모바일 화면을 고려한 반응형 UI

## 게임 흐름

```text
식당 입장
  → 같은 방 코드로 셰프 3명 참가
  → 카드를 드래그해 플레이 순서 결정
  → 전원 준비
  → 4코스의 공정을 차례대로 조리
  → 손님 리뷰 및 하루 정산
  → 다음 날
```

현재 차례의 플레이어만 조리 입력을 사용할 수 있으며, 다른 플레이어는 같은 진행 화면을 관전합니다. 멀티플레이 서버가 방, 플레이 순서, 현재 공정, 공정 점수와 재료 상태를 공유합니다.

## 레시피

| 구분 | 쉬움 | 보통 | 어려움 |
| --- | --- | --- | --- |
| 에피타이저 | 과카몰리 | 브루스케타 | 카프레제 타르타르 |
| 스타터 | 클램 차우더 | 미네스트로네, 프렌치 어니언 수프 | 크림 오브 머쉬룸 |
| 메인 | 로스트 치킨, 미트볼 파스타 | 스테이크 플레이트 | 안심 웰링턴 |
| 디저트 | 애플 타르트 | 크림 브륄레, 블루베리 크럼블 케이크 | 초콜릿 라바케이크 |

매일 자르기, 끓이기, 굽기, 섞기, 마무리 중 한 종류를 선호하는 손님이 등장합니다. 게임 시작 시 첫 손님의 선호 공정을 포함하면서 난이도에 가까운 레시피를 카테고리별로 하나씩 선택하며, 다음 날에는 같은 메뉴를 두고 새 손님을 맞습니다.

## 조작 방식

조리 화면에서 `마이크 켜기`를 누르고 브라우저의 마이크 권한을 허용합니다.

| 공정 | 입력 방식 |
| --- | --- |
| 자르기 | 화면에 표시되는 리듬에 맞춰 `탁`, `찹`, `사각`, `스윽`, `콰직` 등의 소리를 냅니다. |
| 끓이기 | `후우` 소리를 내어 끓이기 진행도를 채웁니다. |
| 일반 굽기 | `후우` 소리로 화력을 올리고, 입을 다물어 화력을 낮추면서 목표 구간을 유지합니다. |
| 오븐 굽기 | 타이머를 보고 목표 시점에 `띵` 소리를 내어 오븐을 멈춥니다. |
| 섞기 | 안내 대본을 읽습니다. 음량과 음성 인식 결과가 움직임과 점수에 반영됩니다. |
| 뿌리기·붓기 | 안내된 음정을 내고 정해진 시간 동안 유지합니다. |

마이크를 사용할 수 없는 환경에서는 성공 입력, 실수 입력과 테스트용 조작 버튼을 사용할 수 있습니다.

### 학습형 음성 인식 AI

조리 음성 분류에는 프로젝트에서 직접 학습한 Teachable Machine Audio 모델을 사용합니다. 브라우저에서 TensorFlow.js와 Speech Commands를 통해 모델을 실행하며, 학습된 `Tak`, `Chap`, `Ssuk`, `Ssak`, `Huu`, `Ting` 등의 음성 클래스를 자르기와 화력 조절 같은 조리 입력으로 변환합니다.

학습 모델은 `src/tm-audio/`의 `model.json`, `metadata.json`, `weights.bin`에 포함되어 있어 음성 분류를 위해 별도의 외부 AI API를 호출하지 않습니다. 오븐의 `띵` 정지 입력과 일부 대본 인식에는 브라우저의 Web Speech API도 함께 사용합니다.

## 점수와 정산

- 각 공정 정확도는 20~100점으로 제한됩니다.
- 코스 점수는 해당 코스에 포함된 공정 점수의 산술평균입니다.
- 기본 최종 점수는 네 코스 점수의 평균입니다.
- 손님이 선호하는 공정을 모두 70점 이상으로 마치면 최종 점수 `+5`, 매출 `+100G`를 받습니다.
- 굽기를 선호하는 손님은 메인 코스의 굽기 공정만 보너스 조건으로 평가합니다.
- 최종 점수는 최대 100점이며 별점은 `ceil(최종 점수 / 20)`, 최소 1개·최대 5개입니다.
- 코스별 매출은 `75 + 코스 점수 × 2`이고, 하루 매출은 네 코스 매출과 손님 보너스의 합입니다.
- 누적 자금이 3,000G 이상이면 식당 등급이 1성에서 2성으로 올라갑니다.

AI는 계산된 결과를 리뷰 문장으로 표현할 뿐 점수와 매출을 변경하지 않습니다.

## 실행 환경

- Python 3.10 이상 권장
- 최신 Chrome 또는 Chromium 기반 브라우저 권장
- 마이크가 있는 장치
- 멀티플레이 시 같은 네트워크에 연결된 브라우저 3개

이 프로젝트는 ES Module과 브라우저 마이크 API를 사용하므로 `index.html`을 파일로 직접 열지 말고 HTTP 서버로 실행해야 합니다.

## 빠른 시작

### 1. 저장소 받기

```powershell
git clone https://github.com/1234jienf/Chop-Chop-Kitchen.git
cd Chop-Chop-Kitchen
```

### 2. Python 의존성 설치

기본 게임과 멀티플레이 서버에는 FastAPI와 Uvicorn이 필요합니다.

```powershell
python -m pip install fastapi "uvicorn[standard]"
```

### 3. 웹 서버 실행

프로젝트 루트에서 실행합니다.

```powershell
python -m http.server 8080
```

브라우저에서 <http://localhost:8080>에 접속합니다.

### 4. 멀티플레이 + GPT 리뷰 서버 실행

별도 PowerShell 창을 프로젝트 루트에서 열어 실행합니다.

```powershell
python -m uvicorn py.multiplayer_api:app --host 0.0.0.0 --port 8001
```

클라이언트는 현재 웹 페이지의 호스트를 기준으로 `ws://호스트:8001/ws`에 연결합니다. 다른 PC에서는 다음 주소로 웹 게임에 접속합니다.

```text
http://서버-PC의-IP:8080
```

필요하다면 Windows 방화벽에서 TCP 8080과 8001 포트의 인바운드 연결을 허용해야 합니다. 방과 진행 상태는 메모리에만 저장되므로 멀티플레이 서버를 재시작하면 초기화됩니다.

## GPT-4o mini 손님 리뷰 설정

손님 리뷰 AI에는 OpenAI의 `gpt-4o-mini` 모델을 사용합니다. 게임에서 계산한 코스별 결과를 Python 서버가 GPT-4o mini에 전달하고, 응답을 감각적인 한국어 미식 리뷰로 표시합니다. AI 리뷰를 사용하지 않거나 요청에 실패해도 게임은 정상 진행되며 내장된 한국어 리뷰가 표시됩니다.

1. 환경 파일을 만듭니다.

```powershell
Copy-Item .env.example .env
```

2. `.env`에 OpenAI API 키를 입력합니다.

```dotenv
OPENAI_API_KEY=your-api-key
```

3. 위에서 실행한 멀티플레이 서버가 리뷰 API도 함께 제공합니다. 별도 리뷰 서버는 실행하지 않습니다.

```powershell
python -m uvicorn py.multiplayer_api:app --host 0.0.0.0 --port 8001
```

- 상태 확인: `GET http://127.0.0.1:8001/health`
- 리뷰 생성: `POST http://127.0.0.1:8001/review`

API 키는 브라우저로 전달되지 않고 Python 서버에서만 읽습니다. `.env`는 Git 추적에서 제외되어 있습니다.

## 마이크와 배포 시 주의사항

- 조용하고 반향이 적은 환경에서 헤드셋 마이크를 사용하면 인식이 안정적입니다.
- `localhost`가 아닌 다른 PC의 일반 HTTP 주소에서는 브라우저 보안 정책 때문에 마이크가 제한될 수 있습니다.
- 외부 배포에서는 웹 페이지를 HTTPS로, 멀티플레이 연결을 WSS로 제공하도록 클라이언트 URL과 서버 구성을 조정해야 합니다.
- 게임 화면에 입력한 서버 주소 하나를 멀티플레이의 `/ws`와 GPT 리뷰의 `/review`에 함께 사용합니다.
- 프런트엔드는 Google Fonts와 jsDelivr의 TensorFlow.js·Speech Commands 라이브러리를 불러오므로 최초 실행 시 인터넷 연결이 필요할 수 있습니다.

## 현재 제한사항

- 공개 플레이 URL이나 패키징된 앱은 제공하지 않으며 로컬 HTTP 서버 실행이 필요합니다.
- 멀티플레이는 정확히 3명이 참가해야 시작할 수 있습니다.
- 멀티플레이 데이터는 영구 저장되지 않습니다.
- 리뷰 API와 WebSocket 주소가 개발 환경 기준으로 고정되어 있어 실제 배포 시 설정 변경이 필요합니다.
- 식당 등급은 현재 1성·2성만 구현되어 있습니다.
