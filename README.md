# Chop-Chop-Kitchen

> 쿠킹마마 스타일의 1인칭 손 시점에서 팀원이 순번대로 코스 요리를 준비하고, 하루가 끝나면 AI 리뷰와 매출로 식당을 성장시키는 협동 경영 게임입니다.

이 저장소는 3명이 5일 동안 제작할 웹게임 데모의 초기 개발 환경입니다. 완성 게임 전체보다 **하루치 조리 → 리뷰 → 정산 사이클을 안정적으로 시연하는 것**을 우선합니다.

## 게임의 핵심 흐름

```text
오늘의 메뉴 확정 → 코스별 순차 조리(릴레이) → 서빙·채점 → AI 리뷰 → 정산 → 다음 날
```

1. 보유 자금과 해금된 레시피 안에서 오늘의 코스를 구성하고 손님의 요구조건을 확인합니다.
2. 각 코스의 자르기·끓이기·굽기 공정을 세 명이 순번대로 담당합니다. 현재 담당자의 1인칭 조리대와 마이크만 활성화됩니다.
3. 음성 패턴과 타이밍의 정확도를 공정별·코스별 점수로 합산하고, 손님 요구조건에 따라 보너스 또는 감점을 적용합니다.
4. 별점과 맛 데이터를 고정 공식으로 계산한 뒤 AI는 계산 결과를 자연스러운 손님 리뷰로 표현합니다. **AI가 점수나 보상을 결정하지 않습니다.**
5. 별점에 비례한 매출로 레시피, 코스 슬롯, 도구의 판정 허용 범위, 재료 등급을 성장시킵니다.

처음에는 에피타이저와 메인의 2코스로 시작하고, 성장하면 에피타이저·스타터·메인·디저트의 4코스까지 확장하는 구상입니다. 다음 날에는 손님이 까다로워지고 정확도 허용 범위가 좁아집니다.

## 계속 플레이하게 만드는 요소

| 장치 | 역할 |
| --- | --- |
| 매일 달라지는 손님 요구조건 | 같은 요리에도 새로운 목표 제공 |
| 별점 → 매출 → 성장 | 실력 향상을 체감할 수 있는 성장 곡선 |
| 레시피·도구 해금 | 다음 날의 선택지와 장기 동기 제공 |
| 식당 등급 1성 → 2성 → 3성 | 팀 전체가 함께 달성할 최종 목표 |

## 실행

ES Module과 마이크 권한 때문에 HTML 파일을 직접 열지 말고 로컬 서버로 실행하세요.

```powershell
cd D:\coding\workspace\Chop-Chop-Kitchen
python -m http.server 8080
```

`python` 명령이 없다면 `py -m http.server 8080`을 사용합니다. 브라우저에서 [http://localhost:8080](http://localhost:8080)으로 접속하세요. GitHub Pages에는 저장소 루트를 그대로 배포할 수 있습니다.

## 현재까지 구현된 코드

- 시작 추천 4코스와 12개 공정 데이터
- 셰프 A → B → C 순서의 릴레이 상태 전환
- 성공/실수 테스트 버튼과 고정 공식 기반 점수·별점·매출
- 실제 마이크 권한 요청과 실시간 볼륨 미터
- 점수 결과를 문장으로 포장하는 로컬 리뷰(추후 AI API 교체 지점)
- 전체 16개 레시피 도감과 14개 음성 패턴 데이터
- 모바일 대응 기본 UI

현재 마이크 코드는 입력 볼륨만 측정하며 음성 패턴을 아직 분류하지 않습니다. 음성 분류가 Day 3까지 안정화되지 않으면 성공/실수 버튼을 실제 게임 입력처럼 연출해 데모 경로를 유지합니다.

## 폴더 구조와 추천 담당

```text
index.html          화면 뼈대
styles.css          공용 스타일·조리 장면
src/
  data.js           레시피·손님·음성 패턴 데이터
  state.js          라운드·릴레이·채점 규칙
  audio.js          마이크 입력과 볼륨 분석
  main.js           화면 렌더링과 이벤트 연결
docs/
  architecture.md   5일간 지킬 범위와 API 경계
```

- 음성 담당: `audio.js`에서 특징 추출과 패턴 분류
- 게임 담당: `state.js`, `data.js`에서 라운드, 채점, 성장 규칙
- UI 담당: `index.html`, `styles.css`, `main.js`에서 1인칭 화면과 연출

## 개발 원칙

브라우저에 OpenAI API 키를 직접 넣지 않습니다. Day 4에 서버리스 함수를 준비한 뒤 클라이언트는 고정 공식으로 계산한 점수와 맛 데이터만 전송하고, AI는 리뷰 문장만 생성하도록 연결합니다. 별점과 매출은 AI 응답으로 덮어쓰지 않습니다.

더 자세한 상태 흐름과 팀 간 인터페이스는 [`docs/architecture.md`](./docs/architecture.md)를 참고하세요.
